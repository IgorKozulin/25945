# BronskiySA — задания 1–9 по операционным системам

В каждой папке `t1`–`t9` находятся исходник на C и Makefile.
Сборка всех программ: `make`. Отдельного задания: `make -C t1`.
Проверка: `make test` (нужен Python 3.9+ с базой часовых поясов).
Очистка исполняемых файлов: `make clean`.

| Задание | Запуск из BronskiySA | Что делает |
| --- | --- | --- |
| 1 | `./t1/options -p -i -d` | Атрибуты процесса, опции выполняются справа налево |
| 2 | `./t2/ex_time` | Текущая дата и время в Калифорнии |
| 3 | `./t3/setuid_test t3/data.txt` | UID и доступ к файлу до и после setuid |
| 4 | `./t4/list_strings` | Динамический связный список, точка в начале завершает ввод |

## Пояснения

### 1. Опции

`-i` UID/EUID/GID/EGID; `-s` setpgid; `-p` PID/PPID/PGID;
`-u` текущий лимит открытых файлов; `-Uчисло` меняет этот мягкий лимит;
`-c` размер core в байтах; `-Cчисло` меняет мягкий лимит core;
`-d` рабочая директория; `-v` окружение; `-VИМЯ=значение` меняет окружение.
Как в подсказках Task_1.txt, под ulimit здесь понимается RLIMIT_NOFILE.
Жёсткие лимиты программа не меняет. Изменения действуют только в её процессе.
Например, `./t1/options -u -U32 -u -U64` выводит 64, затем 32.
`./t1/options -v -VTEST=hello` показывает TEST=hello.

### 2. Часовой пояс

Используется America/Los_Angeles, как рекомендует Task_2.txt:
PST зимой и PDT летом. Исходный общий документ упоминает фиксированный PST;
если преподаватель требует именно постоянное UTC−8, замените TZ на PST8.

### 3. Опыт с двумя пользователями

После получения файлов из Git установите `chmod 600 t3/data.txt`:
Git сохраняет только признак исполнения, а не все биты прав.
Запуск от владельца показывает успешное открытие дважды.
На учебном сервере дайте одногруппнику возможность пройти в каталог и
исполнить программу (`chmod 755 t3/setuid_test`), не открывая ему data.txt.
При обычном запуске другим пользователем оба открытия должны завершиться
ошибкой. После `chmod u+s t3/setuid_test` первый fopen работает с EUID владельца,
после `setuid(getuid())` EUID совпадает с UID запустившего пользователя,
и второй fopen выдаёт ошибку. По завершении опыта: `chmod u-s t3/setuid_test`.
Программу не требуется делать принадлежащей root.
Файловая система с nosuid не позволит продемонстрировать смену EUID.

### 4–7. Строки и таймер

Список сохраняет порядок и пустые строки; getline позволяет вводить длинные
строки. Таблица строк учитывает пустые строки и последнюю строку без перевода
строки. Номера начинаются с 1, 0 завершает работу, неверный ввод повторяет запрос.
В t6/t7 alarm запускается заново для каждого запроса. Обработчик SIGALRM
только устанавливает флаг; вывод и освобождение памяти происходят в main.
pselect атомарно разрешает доставку сигнала во время ожидания ввода.
Даже частично введённый номер без Enter не отменяет таймер.
В t7 данные файла читаются через mmap, выводятся fwrite; прямые read/lseek/write
для данных файла не используются. Не изменяйте файл другим процессом во время поиска.

### 8. Допустимая и обязательная блокировка

По умолчанию fcntl(F_SETLK) ставит неблокирующую блокировку записи на весь
файл (l_start=0, l_len=0). Родитель держит дескриптор открытым, пока system()
выполняет редактор. Второй экземпляр программы на том же файле сразу сообщает
о занятой блокировке; после выхода первого редактора повторный запуск работает.
Задать редактор можно, например, `EDITOR=vi ./t8/locked_editor file.txt`.
Путь к файлу экранируется отдельно, EDITOR — команда, выбранная пользователем.

Допустимые (advisory) блокировки работают, только если программы соблюдают
их: независимый редактор может открыть и изменить файл напрямую.
Блокировка привязана к inode. Сохранение редактором через замену файла
новым inode также может обойти её; для опыта нужен редактор с записью на месте.

Для опыта с обязательной блокировкой на поддерживающем её Solaris:
создайте отдельный учебный файл с групповым правом записи и выполните
`chmod g+s,g-x file.txt`, затем `./t8/locked_editor --mandatory file.txt`.
Поддержка зависит также от файловой системы и её параметров.
Обязательная блокировка применяется ядром и к обычным операциям ввода-вывода.
При этом запущенный через system редактор — другой процесс: он тоже не владеет
родительской блокировкой. Его чтение/запись может заблокироваться, а на некоторых
реализациях завершиться EAGAIN. Поэтому эта схема показывает ограничение
обязательной блокировки и сама по себе не является рабочим защищённым редактором.
Для завершения опыта выйдите из редактора/прервите его и восстановите режим файла.
На Mac режим --mandatory сообщает о неподдерживаемом опыте, не меняя права файла.

### 9. Порядок завершения

Родитель пишет своё сообщение, затем ждёт конкретного ребёнка через waitpid.
Последняя строка родителя появляется после окончания cat даже при перенаправлении
вывода в файл. Входной файл передаётся cat через stdin, что также позволяет
безопасно обрабатывать имя, начинающееся с минуса. Код ошибки ребёнка возвращается
родителем. Ошибка exec заканчивает ребёнка через _exit(127).

## Что проверено

На macOS: сборка всех девяти программ с предупреждениями компилятора;
автоматические проверки опций и ошибок, часового пояса, UID без setuid,
списка с длинными и пустыми строками, таблиц строк, пустого файла и EOF,
пятисекундного таймера с частичным вводом, конфликта и освобождения advisory
блокировки, путей с кавычками, вывода cat на 10 000 строк и порядка завершения.

Проверка с разными пользователями, setuid и обязательной блокировкой на Solaris
пока не выполнена: необходим доступ к учебному серверу и второй пользователь.
Исходники используют интерфейсы POSIX; сборку и поведение на Solaris нужно
подтвердить отдельно (например, `make CC=gcc`).
